the problem

Job hunting is a mess of tabs: postings here, resume versions there, replies in Gmail, and no idea which application got which resume. Existing tools either spray applications automatically (and burn your reputation) or do nothing but store data. I wanted a copilot that drafts everything and sends nothing.

the rule

The human approves every send. The AI drafts, scores and classifies; the person decides. Every AI feature in the app is built around that constraint.

what it does

  • pipeline: paste a posting → requirements extracted → match report against your profile → tailored resume + cover letter → refine chat with undo → version history
  • profiles: 9 profile models, 6 resume themes, PDF export, resume import
  • agent: nightly scan scores new postings and surfaces candidates to approve or dismiss
  • inbox: Gmail sync, reply classification, draft replies with flagged gaps
  • job search: Adzuna, JSearch and FreeHire adapters with 30-minute caching and quota-aware failures
  • calendar: Google OAuth with encrypted token storage, free/busy checks, interview events
  • eight AI tasks: match-requirements, tailor-resume, write-cover-letter, write-email, refine-chat, score-posting, classify-reply, draft-reply — pluggable across OpenAI, Anthropic, Mistral and local Ollama

engineering decisions

  • Next.js 16 App Router + React 19 in strict TypeScript — no any, no suppressions
  • Prisma 7 over better-sqlite3 for zero-ops local storage; Postgres later
  • Sessions are JWE with argon2id password hashing; Google tokens encrypted at rest
  • Test pyramid: Vitest unit + database + contract tests, Playwright E2E
  • zod schemas at every boundary: forms, API routes, AI outputs, adapters
  • a written design spec (12 sections, 6 phases) committed before implementation
