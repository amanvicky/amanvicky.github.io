the idea

AI coding sessions usually end the same way: "this should work". GOD MODE is a single Claude skill file that refuses to end there. It simulates a whole software company whose only law is "proof or it didn't happen" — every quality claim must carry executed test output, benchmarks or scan results.

the pipeline

  • PM: turns your idea into machine-checkable acceptance criteria, compiled into an executable gate script (dod.sh). Shipping literally means exit code 0.
  • rival dev squads: multiple squads build competing implementations; a judge harvests the best parts of each.
  • assault wave: QA executes the suites, SRE runs benchmarks and chaos tests, security audits, a red team attacks from seven user perspectives, and auditors debate the results.
  • CEO scoring: the result is scored 0–10 against a bar of 8.5. Below the bar produces a numbered fix-list and escalating pressure: coach, deadlines, then enforced rewrite by a fresh developer.
  • ship + watcher: after the gate passes, a scheduled watcher monitors dependencies for drift and CVEs and patches the pipeline itself.

the mechanisms that did real work

  • differential testing — critical logic written twice by different algorithms, fuzzed identically, outputs must match. Caught 2 of 3 real bugs in the first run that the normal suites passed clean.
  • mechanical ship gate — run #1 finished at 9/9 suites, 100% line coverage, DOD:PASS.
  • recon gate — every dependency checked against live reality (alive? licensed? CVEs? docs match?) before use; run #1 ended up choosing a zero-dependency strategy because of it.
  • self-rewrite — after every project the skill patches its own rulebook; run #1 added 7 binding rules.

First production run: a complete zero-dependency 2048 game — logic, twin implementation, 9 test suites, UI, docs — from kickoff to shipped bundle in about 23 minutes, including three found-and-fixed bugs and the full audit trail.

one mode, three situations

Building from scratch gets the full pipeline. Handed broken or legacy code, it runs archaeology first — behavior pinned by characterization tests, then smallest-change-first repairs under a behavior-lock. Under deadline pressure it shrinks scope until the remaining core can be finished to the same standard: a complete paperweight, never a half-polished sword, with an exact graduation path for the rest.
